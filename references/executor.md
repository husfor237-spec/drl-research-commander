# 执行者角色规范

## 读取与写入边界

只读 `SKILL.md`、本规范、具体任务书与必要证据。任务接口采用 `references/templates.md`；任务书应给出阶段、冻结规格版本、输入、写入文件/产物目录、预算、验收与停止条件。缺失授权或影响行为的规格时，提交阻塞项。

项目材料统一放在项目 `.codex-run/drl-research/`；实现代码只能写任务书指定位置。只写指定报告、实现和运行产物，保留其他编辑者改动。主帅维护 `state.md`、`control.json`；不能手工改写全局阶段、授权、调度或预算。控制工具自身维护的所有权记录按实际接口更新。

## 运行所有权与预算

1. 先读项目使用的 `project_control.py` 实际帮助/接口以及任务提供的调用方式；不猜参数。调度所有权属于当前主帅会话。执行子代理提交运行记录与配置，由实际持有所有权的会话用 `claim-run` 登记唯一运行 ID，并用 `assert-owner` 验证后调度；不得冒用主帅的 `--owner` 身份。
2. 启动、续跑、重试和改变运行进程/配置前，由实际调度者再次 `assert-owner`。领取失败、所有权变更或检查失败时停止新调度，保留证据并报告；不得通过改 `control.json`、另起别名运行或强制抢占规避。状态/检查点登记由当前所有者按工具接口完成，执行子代理只提交证据。
3. 工具缺失或无法验证所有权时，不启动训练，提交可完成的静态检查及阻塞项。获准运行仍须满足任务预算、并发和阶段限制；只领取所有权不等于获准扩大预算。
4. 监控已用与预计剩余资源，在耗尽预算或触发停止条件前记录状态并按协议安全停下。未经任务授权不终止他人的进程，不扩展搜索或追加种子。

## 实现与环境验收

对照冻结规格检查，报告预期、实际和证据，不能只写“测试通过”：

| 检查 | 最小可复核证据 |
| --- | --- |
| 时间顺序 | 到达、可见信息、决策、占用/释放、完成、奖励的事件轨迹；同刻事件顺序与越界索引 |
| 边界 | 零任务/零资源、满容量、无合法动作、终止/截断、极端时长与数值输入；按规格处理或明确拒绝 |
| 资源守恒 | 每步容量、占用、释放、队列/任务流转的守恒断言；不能重复分配、漏释放或产生负资源 |
| 约束 | 合法动作集、掩码依据、违例检测和无合法动作语义；修复不按业务目标选优或排序 |
| 泄漏 | 观测字段可用时刻、生成器/归一化拟合范围、训练验证测试隔离；评价标签不进入策略 |
| 复现 | 最小实例的可手算答案、固定种子回放、独立进程配置复跑；非确定性来源和合理容差 |

所提方法及训练路径禁止模仿、专家示范、教师监督、启发式暖启动、物理引导网络或损失、人工调度优先级、额外奖励塑形。真实物理环境、原始目标、传统基线和只排除非法动作的可行性处理允许；基线不能变成候选方法的教师或暖启动源。

基线先确认目标、信息、动作约束、实现来源与超参数口径，再按冻结验收标准比较原文报告和本地结果。环境或基线失败未解释时，只执行获准的定位/修复和小规模复查，停止大规模调度；不能删除失败实例或调环境让候选获胜。

## 每次运行的证据包

使用全项目唯一运行 ID。新配置、新种子或独立重跑用新 ID；同一训练的合法续跑保留逻辑训练链关联，另记续跑/尝试 ID 和父记录。已经登记为完成/失败的运行不得重新领取或启动：需要恢复时用新的调度运行 ID，引用原运行和检查点，并标明属于续跑而非独立样本。不覆盖旧日志。清单至少持久化：

- 任务 ID、阶段、规格/协议版本、运行/尝试 ID、所有者、父运行或检查点、状态、开始/结束时间与退出码。
- 代码提交与工作区改动快照或内容哈希；环境/仿真版本、运行时、依赖锁定/实际版本、硬件和设备信息。未提交改动不能只记 Git HEAD。
- 完整配置及哈希、训练/评价/环境种子、数据与场景版本/哈希、训练验证测试归属、精确启动命令和工作目录。命令中凭据须脱敏。
- 标准输出/错误日志、逐次评价原始指标、聚合规则、检查点、约束违例、异常/超时/失败记录、墙钟时间及算力/内存成本。

单次最优值不能代替多次运行。正式实验严格按冻结的种子、预算和调参范围执行；不依测试结果选 checkpoint、删种子或追加有利场景。失败、约束违例和不确定性按协议纳入报告。

## 长训练与交接

启动后立即持久化进程/作业 ID、所在机器、运行 ID、配置和所有权；训练期间按约定保存进度、预算消耗、最后可靠检查点及检查点哈希、下一检查时点和监控入口。

续跑需保存模型、优化器/调度器、随机状态、步数和算法必需的回放/采样状态；缺失时标注为重新开始或非精确恢复，不能声称无缝续跑。训练/评价数据依赖和精确恢复命令也写入任务指定交接文件。

模型上下文压缩或会话恢复不等于重启训练。恢复时先读取交接产物、检查现有作业与所有权，再决定监控、续跑或报告失效。已有活跃作业时不得重复启动；失效作业也须按协议重新验证所有权及剩余预算。

## 交付与失败动作

提交实现差异、验收证据、运行清单与结果、失败原因、预算消耗、可复核复跑方式及剩余问题。异常时保留日志和部分产物，区分代码错误、环境假设问题、资源故障与算法负结果；不能把未知原因写成已解释。

主帅决定是否过闸、修订规格或扩大预算。对话只给简短结论、活跃运行/阻塞项和报告/证据绝对路径，完整内容落盘。
